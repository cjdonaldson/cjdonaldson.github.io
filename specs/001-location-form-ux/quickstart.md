## What This Feature Does

Improves `camping/location-form.html` — the internal tool used to generate JSON
entries for the Florida Bound trip planner. Four changes are made:

1. **Seven named sections** replace four poorly-named sections; fields are regrouped
   to match their section's topic.
2. **Multi-column rows** for Name/Emoji, City/State/ZIP, and Phone/Email reduce the
   form's scroll height.
3. **"(optional)" text removed** from all field labels; the existing `*` marker
   already communicates required vs. optional.
4. **Booking radio interaction** replaces two independent booking text/URL fields
   with a "Call to Book" / "Book Online" radio choice that enforces mutual
   exclusivity in JSON output.

## How to Test

### 1. Open the form

```
Open camping/location-form.html directly in a browser (file:// or local server).
```

### 2. Check section headers

Scroll top to bottom. Headers must appear in this order:
Identity → Address → Coordinates → Contact → Web & Resources → Booking → Additional Details

### 3. Check multi-column layout

At a typical desktop width (≥ 1024 px):
- Name and Emoji appear side-by-side on one row
- City, State, and ZIP appear side-by-side on one row
- Phone and Email appear side-by-side on one row
- Latitude and Longitude appear side-by-side (unchanged)

### 4. Check responsive collapse

Resize the browser window below 400 px wide. Every multi-column row must stack to
a single column. No horizontal overflow or overlapping fields.

### 5. Check "(optional)" removal

Use browser Find (Ctrl+F / Cmd+F) to search for "(optional)" on the rendered page.
Zero results expected.

### 6. Test the Booking radio interaction

1. Confirm "Call to Book" is selected by default and no URL input is visible.
2. Select "Book Online" → a Booking URL input appears.
3. Enter a URL (e.g., `https://reserveamerica.com/example`).
4. Switch to "Call to Book" → URL input disappears; value is preserved.
5. Switch back to "Book Online" → URL is restored.
6. Click "Generate JSON":
   - With "Book Online" + URL: output contains `bookingUrl`, no `booking`
   - With "Call to Book": output contains neither `bookingUrl` nor `booking`
   - With "Book Online" + empty URL: output contains neither key

### 7. Test "Clear Form"

1. Fill several fields, select "Book Online", enter a URL.
2. Click "Clear Form".
3. Confirm: all fields empty, radio back to "Call to Book", URL input hidden,
   JSON panel hidden.

### 8. Verify all JSON keys

Generate JSON for a fully-filled form. Verify the output contains these keys
(all non-empty fields): `name`, `emoji`, `coords`, `zip`, `city`, `state`,
`address`, `url`, `mapUrl`, `siteMap`, `contactUrl`, `bookingUrl`, `phone`,
`email`, `emailName`, `hours`, `season`, `distances`, `features`, `notes`,
`defaultStart`.

## Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| CSS Grid for multi-column rows | Matches existing `coords-group` pattern; zero dependencies |
| Single `@media (max-width: 399px)` rule | Spec requirement (FR-037); one rule handles all multi-column rows via shared `.form-row` class |
| `display: none` / `display: block` toggle | Spec requirement (FR-025); instant toggle, no animation |
| URL field hidden but not cleared | Spec requirement (FR-024); prevents accidental data loss when switching radios |
| `bookingUrl` gated on radio state in JS | Ensures hidden URL is never emitted; enforces mutual exclusivity (FR-028) |
| `booking` key removed entirely | Replaced by implicit absence of `bookingUrl`; backward-compatible per spec clarification |
